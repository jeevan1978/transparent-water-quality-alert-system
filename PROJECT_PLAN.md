## 1. Executive Summary & Objective

The **Transparent Water Quality Alert System** is an educational and operational prototyping platform designed to monitor, classify, forecast, and generate alerts for aquatic environments. The system ingests high-frequency water telemetry (pH, Turbidity, Dissolved Oxygen, Temperature, Conductivity, Total Dissolved Solids), categorizes current status into **Good**, **Needs Treatment**, or **Poor**, projects numerical water parameters across **6-hour** and **24-hour** horizons, evaluates future quality shifts, and dispatches proactive operational alerts.

### Critical Disclaimer
> **MANDATORY NOTICE:** All telemetry datasets utilized, generated, and demonstrated within this project are **100% synthetic/simulated**. They are created for educational modeling and algorithm prototyping only. The outputs, forecasts, and alerts generated by this system **must never be construed as statutory verification of drinking-water safety or used for regulatory public health compliance**.

## 3. Core Functional Components

### 3.1 Simulated Data Generation (`src/data_simulator.py`)
- **Telemetry Parameters:**
  - `ph`: Baseline 7.0–7.8, diurnal fluctuation ~0.2, physical range [0.0, 14.0].
  - `turbidity`: Baseline 0.5–3.0 NTU (gamma distribution), physical range [0.0, 100.0].
  - `dissolved_oxygen`: Baseline 6.5–9.0 mg/L with diurnal photosynthetic peaking, physical range [0.0, 15.0].
  - `temperature`: Diurnal peak in mid-afternoon, range [15.0, 30.0] °C.
  - `conductivity`: 200–500 µS/cm baseline.
  - `total_dissolved_solids`: Scaled correlation to conductivity.
- **Anomaly Modeling:**
  - `runoff`: Spikes turbidity (>15 NTU) and conductivity (>800 µS/cm).
  - `acid_spike`: Rapid depression of pH below 6.0.
  - `hypoxia`: Depletion of dissolved oxygen below 4.0 mg/L.
- **Station Support:** Multi-station telemetry simulation (`Station-Alpha`, `Station-Beta`, `Station-Gamma`).

### 3.2 Preprocessing & Feature Engineering (`src/preprocessing.py`)
- **Cleaning:** Missing value interpolation, timestamp sorting, physical clamping.
- **Cyclical Features:** $Hour_{sin} = \sin(2\pi \cdot hour / 24)$ and $Hour_{cos} = \cos(2\pi \cdot hour / 24)$.
- **Lag Features:** Lag steps $t-1$, $t-3$, $t-6$ for temporal autocorrelation.
- **Scaling:** Scikit-Learn `StandardScaler` fitted and serialized for repeatable inference.

### 3.3 Current Quality Classification (`src/current_classifier.py` & `src/labeling.py`)
- **Target Classes:**
  1. `Good`: Parameters satisfy safe ecological/potability benchmarks.
  2. `Needs Treatment`: Moderate elevation of turbidity, pH drift, or reduced DO requiring filtration/aeration.
  3. `Poor`: Severe deviations (hypoxia < 4.0 mg/L, pH < 6.0 or > 9.0, turbidity >= 15 NTU).
- **Model Architecture:** Random Forest Classifier (100 estimators, balanced class weights).
- **Resilience:** Built-in automatic fallback to deterministic domain rules if unpickled model weights are missing.

### 3.4 Numerical Forecasting & Future Category Prediction (`src/forecasting.py`)
- **Horizons:** 6-Hour ($t+6h$) and 24-Hour ($t+24h$).
- **Numerical Forecast:** Multi-output Random Forest Regressor predicting all six parameter values at the horizon.
- **Future Category Prediction:** Ingests the forecasted parameter vector into the classifier to predict future class (`Good`, `Needs Treatment`, `Poor`) and synthesize a human-readable explanation of expected deterioration.

### 3.5 Alert & Early Warning Engine (`src/alert_engine.py`)
- **Alert Types:**
  - `THRESHOLD_BREACH`: Instantaneous sensor violation (e.g. current pH = 5.4).
  - `PREDICTIVE_DEGRADATION`: Early-warning alert generated when future conditions at +6h or +24h degrade to `Needs Treatment` or `Poor`.
- **Severity Levels:** `INFO`, `WARNING`, `CRITICAL`.
- **Operator Guidance:** Each alert includes an actionable `recommended_action` (e.g. "Activate auxiliary aeration impellers", "Switch intake manifold to reserve reservoir").

### 3.6 Data Layer & Supabase PostgreSQL (`src/database.py`)
- **Cloud Database:** Supabase managed PostgreSQL instance.
- **Schema:**
  - `telemetry_readings`: Stores time-series observations with station IDs and synthetic markers.
  - `predictions`: Logs model forecast runs and projected metrics.
  - `alerts`: Tracks active and resolved notifications.
- **Offline Fallback:** Automatic zero-configuration fallback to a local SQLite database (`data/local_water_quality.db`) if Supabase environment variables are unset.

### 3.7 Interactive Streamlit Dashboard (`app.py`)
- Station selector and time range filtering.
- Synthetic data disclaimer banner.
- High-level KPIs: Current Quality Status, Mean Dissolved Oxygen, Peak Turbidity, Active Alert Counts.
- Interactive Plotly time-series charts with safe threshold reference lines.
- Horizon forecast cards (+6h and +24h predictions with confidence indicators).
- Real-time Alert center with severity badges and operator checklists.
- Synthetic simulation control trigger to inject simulated anomalies on demand.

## 4. Team Work Breakdown Structure (5 Team Members)

To facilitate clean parallel collaboration, work is distributed across five specialized roles:

### Team Member 1: Data Simulation & Sensor Telemetry Lead
- **Module Ownership:** `src/data_simulator.py`, `scripts/generate_data.py`, `tests/test_simulator.py`.
- **Core Responsibilities:**
  1. Refine diurnal math models and seasonal climate variability for simulated stations.
  2. Implement realistic sensor failure modes (flatlining, sensor drift, dropped packets).
  3. Build CLI generator options for bulk synthetic dataset creation (`--days`, `--stations`, `--noise`).
  4. Author unit tests verifying physical limits, schema compliance, and anomaly triggers.

### Team Member 2: Preprocessing, Feature Engineering & Labeling Lead
- **Module Ownership:** `src/preprocessing.py`, `src/labeling.py`, `config/thresholds.yaml`.
- **Core Responsibilities:**
  1. Maintain threshold configuration in `config/thresholds.yaml` aligned with WHO/EPA guidelines.
  2. Implement rolling statistical windows (e.g. 6h rolling mean, standard deviation, rate of change).
  3. Formulate a quantitative Water Quality Index (WQI) score (0–100) alongside categorical labels.
  4. Build pipeline transformers with persistent scalers (`scaler.joblib`).

### Team Member 3: Machine Learning & Time-Series Forecasting Lead
- **Module Ownership:** `src/current_classifier.py`, `src/forecasting.py`, `scripts/train_models.py`, `tests/test_classifier.py`, `tests/test_forecasting.py`.
- **Core Responsibilities:**
  1. Benchmark Random Forest against Gradient Boosting (LightGBM/XGBoost) for classification.
  2. Implement time-series cross-validation (`TimeSeriesSplit`) to prevent data leakage.
  3. Train and tune 6-hour and 24-hour multi-output parameter forecasters.
  4. Calculate prediction confidence intervals (e.g. 95% quantile bounds) for future parameter values.

### Team Member 4: Alert Intelligence & Cloud Database Lead
- **Module Ownership:** `src/alert_engine.py`, `src/database.py`, `tests/test_alerts.py`, `.env.example`.
- **Core Responsibilities:**
  1. Author PostgreSQL schema DDL and migrations for Supabase tables.
  2. Implement alert throttling and deduplication to prevent operator alarm fatigue.
  3. Write notification webhooks (Slack/Teams/Email) for critical predictive alerts.
  4. Ensure robust offline SQLite fallback mode for local testing without internet access.

### Team Member 5: Streamlit UI, Visualization & Deployment Lead
- **Module Ownership:** `app.py`, `requirements.txt`, `README.md`, Docker configuration.
- **Core Responsibilities:**
  1. Build the Streamlit dashboard layout using responsive tabs, metrics, and Plotly charts.
  2. Design visual indicators (color-coded badges for Good, Needs Treatment, Poor).
  3. Implement the on-demand simulation test trigger for live anomaly demonstration.
  4. Prepare deployment configurations for Streamlit Community Cloud or Docker containers.

## 6. Testing & Quality Assurance Plan

1. **Unit Testing (`pytest tests/`):**
   - Verify data simulator bounds, schema format, and synthetic flags.
   - Test rule-based label assignments against edge-case readings.
   - Verify classifier prediction outputs and fallback mechanisms.
   - Validate 6h and 24h forecasting dimensions and parameter boundaries.
   - Confirm alert triggers for both instantaneous breaches and predicted degradation.
2. **Integration Testing:**
   - Run end-to-end simulation -> database insert -> model inference -> alert creation pipeline.
3. **Reproducibility Checks:**
   - Seeded random number generation ensuring identical training distributions across platforms.
